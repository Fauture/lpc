fix: 开新手礼包把 GS 栈溢出打崩（1MB→32MB）+ 任务 log/tip 全空（efun 闭包被误当成函数调用）

I1 src/CMakeLists.txt: 调度器跑在主线程（main.cpp -> lpc::schedulerRun()），
所有 LPC 调用都嵌套在主线程栈上；/STACK:0x100000（1MB）下开新手礼包约 100 层嵌套
（apply -> open_newgift_item -> rebuild_newbie_gift -> new_item -> move_to_bag ->
put_in_container -> refresh_item -> build_item_ex -> get_item_basic_info -> ...）
直接 0xC00000FD 把整个 GS 打死（原版 Linux 默认 8MB）。
改为 /STACK:0x2000000（32MB）；顺带让 checkCallDepth(400 帧) 真正生效
（1MB 时 400 帧需 ~4MB，永远到不了就先崩；32MB 下会抛可被 catch 的 VmError）。

I2 src/value.h + src/original_vm.cpp: op23 建的 efun 闭包
（(: call_other, path, "fn" :)、(: create_thread, ... :)）是 func=nullptr、
funcIndex=<efun 全局槽号>、owner=nullptr。call_fun_ptr(case5) 在走到 efun-by-name
兜底之前先跑 funcsByIndex_[funcIndex] / findMasterFunction(funcIndex)，
而 efun 槽号与合并函数表的下标空间重叠：当前 VM 表在该下标有函数时，
闭包会静默调用那个无关函数。taskd 的 (*funcs["tip"])(me, task_info) 因此返回 int 1
而不是 instruction_1::task_tip 的字符串 -> is_string 失败 -> 任务 log/tip 全空。
新增 ClosureValue::efunClosure 标记，创建处置位、两处闭包拷贝一并复制，
call_fun_ptr 的该分支加 !cl->efunClosure 让它落到 efun 兜底。
