# 操作码语义参考（IDA 采集，magic_Linux32x）

> 全部 85 个操作码（0x00–0x55）处理函数已从 IDA 反编译采集，伪代码存
> `_ida_out/addr_<地址>.c`（如 `_ida_out/addr_0808e3b8.c` = vm_addValue）。
> 表格列：op / hex / 名称 / 处理函数(地址) / 参数数 / 语义。
> 「参数」列含义见 `docs/原版VM核心处理.md` §4（0/1/2 = immediate 个数；
> 257/258 = metaData 模式 1/2 参数）。栈方向：push 为 `--vm_sp`，右操作数在
> `stack[sp]`、左在 `stack[sp+1]`，结果写回左槽。

## 与重实现（src/vmcore/interp.cpp）的核对锚点

- op27(0x1b) enter_function：压槽数 = 函数头 semValue 高 16 位 = .o 函数头 64B 里的
  localVariables（实测与 convert_to_value 一致，实现无错）。
- op18/op80 的 ip 增量方向（上表已注）曾实测验证（勿再猜）。
- op73(0x49) 返回值"恒恰 1 个、无则 pushVoid"——C 侧 efun 包装必须遵守
  （vm_returnFromEfun 0x08093c5c 单次 pushValue 交付）。
- op8(0x08) 数组广播路径的 hook 返回回调（callInOtherFunExReturn）对应我们
  hook 链"末元素经 rv 出参交付"铁律。
- query_range_ptr(0x46) 原版即 noreturn 报错——重实现无需支持范围引用。
