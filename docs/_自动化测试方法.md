# 登录流程自动化测试方法（本地引擎）

## RDP 真实客户端测试（人机验证，强制用于游戏内问题）当此项不可用时使用模拟脚本进行测试

协议探针（`_login_lib.py` / `_enter_probe.py` / `_menu_drive.py`）只能验证到包级；
"指引光效/对话头像/道具使用提示"这类**客户端表现**必须用真实客户端验证。

**前提（已确认可用）**
- 客户端：`E:\bf\BaiduNetdiskDownload\asktao1.60\arun.bat`（GBK 编码，内容为
  `start asktao.mod 试剑内测;192.168.200.1;8001;kbd:0;swictch:0;proxy:0;flag:;uncheck`）。
- 当前 DSH 进程所在会话 = RDP 活动会话（`qwinsta` 里 `rdp-tcp#42 Administrator 1 Active`，
  shell 的 `SessionId` 也是 1），所以截图与输入自动化直接作用在同一个桌面上。

**截图（必须先压缩再上传）**
```
python -X utf8 _shot.py [out.jpg] [maxwidth] [quality] [x y w h]
# 默认：全屏、宽 1280、质量 55 -> 约 70KB（1920x1080 源）
# 只截游戏窗口：先 python -X utf8 _ui.py find 问道 拿到 rect，再传 x y w h
```

**UI 自动化（ctypes，无依赖）**
```
python -X utf8 _ui.py list                     # 列出可见窗口（标题/rect/pid）
python -X utf8 _ui.py find <标题子串>          # 找窗口
python -X utf8 _ui.py focus <标题子串>         # 前置窗口
python -X utf8 _ui.py click <x> <y>            # 点击（屏幕坐标）
python -X utf8 _ui.py key {ENTER}abc           # SendKeys
python -X utf8 _ui.py paste "<中文文本>"       # 剪贴板 + Ctrl+V（中文安全）
```

**标准人机流程**
1. 清库启动：`python -X utf8 _run_probe.py <dir> 21600 "LPCVM_..."`（自动清 `dl_ddb_1_test`）。
2. 等 8160 LISTEN；建号：`python -X utf8 _login_full.py 192.168.200.1 8001 2 2`
   （账号 2/2，角色名 ASCII，例如 awesrd；首个角色可绕过名字规则）。
3. 启动客户端：`cmd /c start "" "E:\bf\BaiduNetdiskDownload\asktao1.60\arun.bat"`
   （或在该目录双击；若窗口在后台，用 `_ui.py focus 问道` 前置）。
4. `_shot.py` 截图确认登录界面 → `_ui.py click/paste` 输入账号密码 → 进游戏。
5. 复现问题（走路/点 NPC/用道具/查看装备栏），每步 `_shot.py` 截图；
   同时对照服务端日志 `<dir>\live_gs.txt`（`[case8]` 跨对象派发、`[temp-op]`、`[iiddbg]` 等探针）。
6. 结论写清：截图证据 + 服务端日志证据 + 复现步骤。

**红线**
- 仍然只允许清空 `dl_ddb_1_test`；`dl_adb_all_test` 只读；禁止手工造数据绕过问题。
- 客户端登录必须让服务端自己建角色（`create_new_char`），不要往 `dl_mdb_1` 塞行。
- 若 RDP 不可用（会话不一致 / 截图全黑 / 无法输入）→ **停止并如实报告"无法使用 RDP 测试"**，
  不要假装做过人机验证。


## 🖱️ 客户端必经弹窗的正确点法（人机/自动化都照这个来） 当此项不可用时使用模拟脚本进行测试

1. **选服 / 区组界面** → 点 **取消**（不要点“确定”，否则又回到区组列表）；
2. **「重新登录游戏，需要再次进行安全验证」** → 点 **确定**，即可回到登录界面；
3. 回到登录界面后：账号框输入账号 → `Tab` → 密码框输入密码 → **回车**（回车等同“进入游戏/确定”）；
4. 建角界面：点“创建角色” → 选门派 → 点“角色名字”输入框 → 输入名字（该输入框**只接受 WM_CHAR**，
   SendKeys/SendInput 会被客户端丢弃）→ 点“创建角色” → 点“进入游戏”；
5. 剧情右下角 **跳过**；任务追踪（右上角）点一下会自动寻路到目标 NPC。

对应脚本（`_rdp.py`）：`BTN_SERVER_CANCEL` 用于第 1 条，`BTN_VERIFY_OK` 用于第 2 条，
`fastlogin` 走第 3 条，`makechar` 走第 4 条，`auto` 把这些串成一条命令。


## 🔁 登录验证的顺序：先操作真实客户端，确定无法操作才用模拟脚本

**必须先对客户端操作**（RDP 已连接、客户端窗口存在时，一律先用真实客户端跑登录/游戏内验证）：

1. 判断 RDP 是否可用：`qwinsta` 能看到 `rdp-tcp#` 会话、且 `_rdp.py rect` 能找到客户端窗口；
2. **可用 → 走客户端**：`python -X utf8 _rdp.py auto <账号> <密码> <角色名>`（起客户端→登录→建角→进游戏），
   截图用 `python -X utf8 _shot.py out.jpg 800 60 client`（压缩后再看）；
3. **只有 RDP 没连接、或反复确认客户端操作必定做不到时**（例如客户端窗口不存在、
   反外挂弹窗无法越过、注入输入被拒），才退回**模拟脚本**验证登录：

```
python -X utf8 _login_full.py 192.168.200.1 8001 <账号> <密码>      # 建号/登录/进图
python -X utf8 _autotest.py <账号> <密码> <角色> selfid|dump         # 协议级用例
python -X utf8 _relogin_test.py 192.168.200.1 <账号> <密码> <角色>   # 上下线 + 过图回归
python -X utf8 _fire_special.py <账号> <密码> <角色>                 # 剧情触发点
python -X utf8 _bagtask_probe.py <账号> <密码> <角色> <秒>           # 任务面板 + 背包
```

约定：
* **不允许跳过客户端操作直接上模拟脚本**；模拟脚本是“客户端确实无法操作”时的替代手段；
* 用模拟脚本时选**独立账号**，别和客户端占同一个号（否则客户端会弹
  「重新登录游戏，需要再次进行安全验证」）；
* 判定：客户端能进游戏（标题栏 `[一线] [角色名]`）或模拟脚本走到“进入地图/收到角色数据包”即视为登录通过。
