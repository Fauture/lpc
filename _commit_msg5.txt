症状：dl_ddb_1_test.data 里角色 dbase 只在创建时写过一次（user/<gid>=1520B, carry=17B），
之后等级/物品/newbie 标记全丢，重上每次重跑新手剧情，礼包 gift_info 没恢复 ->
is_empty() 为真 -> apply 走 rebuild_newbie_gift 生成新礼包（本该弹列表）。

J1 src/game_service.cpp: 客户端 socket 关闭时驱动从不通知 LPC。原版会
vm_apply("cmd_disconnected", cno, where) -> start_gs::_cmd_disconnected ->
user.o::disconnected -> set_timer(180,"time_expired") -> destruct ->
userd::destroy_user -> me->save(0,cb)（唯一写回角色 dbase 的路径）。
改为在 client slot 注销前调用 cmd_disconnected(cno, 2)。

J2 src/original_vm.cpp callDestructors: 原来按 funcsByIndex_ 下标顺序跑所有 destruct，
继承来的 carry.c::destruct 先跑并把 lite_set_temp("destructing",1) 置位，
而 user.o::save 开头就是 if (destructing || destructing_store) return 1 ->
注销存盘直接 return 1（FNTRACE 实录 ENTER save / RETURN save ret=1，无 ::save/无 filed 写入）。
改为按 (funOffset, index) 升序稳定排序：对象自身程序(funOffset=0)先跑，继承的依次在后。

J3 destructObjectByKey: 原来先摘 reg.vms/objects/initialized 再跑析构，
而析构链要回调本对象（destroy_user -> me->save、carry.c 逐件 destruct_object），
call_other 靠 reg.vms 解析 -> 全成空操作。改为先跑析构再摘；析构链内再次
destruct_object(同 key) 直接返回，由外层负责拆除。
